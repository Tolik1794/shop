# Pricing services

Цей каталог містить сервіси для визначення каталожної ціни товару в потрібній валюті.

## Для чого існує цей шар

Ціна товару потрібна в кількох місцях одночасно:

- у пошуку товарів для замовлення;
- під час автоматичного заповнення ціни нової позиції замовлення;
- у майбутніх правилах ціноутворення.

Щоб ці місця не почали рахувати ціну по-різному, базове визначення каталожної ціни зібране в одному сервісі — `CatalogPriceResolver`.

## Класи

- `CatalogPriceResolver` — знаходить актуальну регулярну ціну товару в потрібній валюті.
- `ResolvedPrice` — результат визначення ціни: сума, валюта і джерело значення.

## Поточне правило визначення ціни

`CatalogPriceResolver` працює в такому порядку:

1. шукає актуальний `ProductPrice` типу `REGULAR` для потрібної валюти;
2. якщо його немає, бере `Product.baseSalePrice`;
3. якщо потрібна валюта відрізняється від базової валюти магазину, конвертує `baseSalePrice` через `ExchangeRateResolver`.

Це один спільний шлях для frontend-пошуку товарів і backend-збереження замовлення.

## Коли використовувати `resolve()` і `tryResolve()`

- `resolve()` — коли без ціни операцію не можна коректно завершити. Наприклад, при автоматичному заповненні ціни позиції замовлення.
- `tryResolve()` — коли відсутність автоматичної ціни не повинна ламати сценарій. Наприклад, у пошуку товарів, де менеджер ще може ввести ціну вручну.

## Межі відповідальності

- Цей модуль визначає лише **базову каталожну ціну**.
- Він не рахує підсумки замовлення, не застосовує знижки рядка і не повинен знати про оплату чи доставку.
- Майбутні правила на кшталт уцінки, знижок на залишки або пріоритетних сценаріїв продажу мають розширювати цей шар, а не дублювати логіку в контролерах чи менеджерах.
