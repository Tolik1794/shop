Потрібно покращити UX/UI сторінки списку категорій в адмінці.

Поточна проблема:
- категорії та підкатегорії відображаються як звичайний список посилань;
- вкладеність підкатегорій погано читається;
- активна категорія майже не виділена;
- права панель деталей виглядає відірваною від списку;
- незрозуміло, як створити саме підкатегорію для вибраної категорії.

Задача:
1. Переробити список категорій у вигляд дерева.
   - Категорії верхнього рівня мають бути без відступу.
   - Підкатегорії мають мати візуальний відступ.
   - Для категорій з дітьми показувати індикатор розгортання/згортання.
   - Вкладеність має читатися візуально.
   - Стилі виконати у стилі поточного проєкту, без додавання нових UI-бібліотек.

2. Додати активний стан вибраної категорії.
   - Активна категорія має мати фон або інше чітке виділення.
   - Активний стан має бути помітним краще, ніж просто синій текст.
   - Hover-стан для категорій також має бути акуратним і зрозумілим.

3. Додати швидкі дії для категорії.
   - Для кожної категорії на hover показувати невеликі дії:
     - редагувати;
     - додати підкатегорію;
     - додаткові дії, якщо такі вже є в проєкті.
   - Не перевантажувати список кнопками, якщо користувач не навів курсор.

4. Покращити кнопку створення.
   - Основну кнопку назвати “Нова категорія”.
   - У правій панелі для вибраної категорії додати дію “Додати підкатегорію”.
   - Створення підкатегорії має передавати вибрану категорію як parent, якщо така логіка вже існує.

5. Покращити праву панель деталей.
   - Показувати назву категорії.
   - Показувати опис, якщо він є.
   - Показувати шлях категорії, наприклад: “Категорії / Стелажі / Модулі”.
   - Показувати батьківську категорію.
   - Показувати кількість підкатегорій, якщо ці дані доступні.
   - Показувати основні дії: “Редагувати”, “Додати підкатегорію”.
   - Не дублювати одне й те саме поле без потреби.

6. Покращити breadcrumb.
   - Breadcrumb має відображати повний шлях до вибраної категорії.
   - Для підкатегорії має бути формат: “Категорії > Стелажі > Модулі”.
   - Якщо вже є компонент breadcrumb, використати його.

7. Додати empty state.
   - Якщо категорія не вибрана, у правій панелі показати повідомлення:
     “Виберіть категорію зі списку, щоб переглянути деталі або додати підкатегорію.”
   - Empty state має виглядати акуратно в стилі проєкту.

8. Переглянути кнопку “Фільтр”.
   - Якщо реального функціоналу фільтрації немає, прибрати її.
   - Якщо фільтр потрібен, зробити його конкретним: активні/приховані/без товарів/верхній рівень.

9. Додати пошук по категоріях, якщо це не потребує великої переробки.
   - Поле пошуку розмістити над деревом категорій.
   - Пошук має фільтрувати категорії по назві.
   - Якщо дерево має вкладеність, при знайденій підкатегорії має бути видно її батьківську категорію.

Обмеження:
- Не змінювати бізнес-логіку без потреби.
- Не додавати нові залежності без окремого погодження.
- Не ламати існуючі route names, form field names, JS selectors, data attributes і translation keys.
- Не змінювати виконані міграції.
- Стилі робити в межах існуючої дизайн-системи/стилю проєкту.
- Зміни мають бути невеликими і поетапними.

Очікуваний результат:
- сторінка категорій виглядає як зручний менеджер дерева категорій;
- користувач чітко бачить вкладеність;
- зрозуміло, яка категорія вибрана;
- легко додати підкатегорію;
- права панель показує корисну інформацію про вибраний елемент.
