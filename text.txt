Потрібно покращити UX/UI шаблонних CRUD index-сторінок адмінки без зміни бізнес-логіки.

Контекст:
- Проєкт на Symfony 7.4.
- Не змінювати існуючі routes, form field names, JS selectors, data attributes і translation keys без окремого погодження.
- Не змінювати вже виконані migrations.
- Не додавати нові залежності без погодження.
- Зміни мають бути невеликими та ізольованими.
- Перед редагуванням показати короткий план.
- Після редагування показати список змінених файлів.

Задача:
Створити або покращити універсальний UI-шаблон для CRUD index-сторінок адмінки на прикладі сторінки платежів.

Що потрібно зробити:

1. Page header
- Додати зрозумілий заголовок сторінки.
- Додати короткий subtitle/description.
- Breadcrumbs залишити як допоміжну навігацію.

2. Index toolbar
- Додати універсальний toolbar над таблицею.
- Toolbar має підтримувати:
  - пошук;
  - кнопку фільтрів;
  - кнопку створення нового запису;
  - місце для майбутніх додаткових дій.
- Якщо пошук або фільтри вже існують, використати існуючу логіку, не переписувати її повністю.

3. Table UX
- Покращити читабельність таблиці.
- Додати hover state для рядків.
- Грошові значення вирівняти вправо.
- Колонки з технічними значеннями зробити візуально менш шумними.
- Додати єдиний стиль для row actions, якщо вони вже є або можуть бути додані без зміни логіки.

4. Badges
- Створити або використати існуючий універсальний badge-компонент/partial.
- Значення типу direction/status/type показувати як badge, а не як звичайний текст.
- Для payment direction:
  - incoming показувати як "Incoming" або поточний переклад;
  - outgoing показувати як "Outgoing" або поточний переклад.
- Для payment type:
  - cash показувати як badge.

5. Detail / preview panel
- Поточний блок деталей платежу оформити як preview/detail panel.
- У верхній частині панелі показати:
  - назву/ідентифікатор платежу;
  - документ;
  - badges direction/type;
  - основну суму.
- Нижче згрупувати деталі у зрозумілі label/value рядки.
- Дії над записом, наприклад "Сторнувати", перенести у зрозумілу action area.
- Небезпечні дії оформити як secondary/danger-outline, не як primary action.

6. Empty/loading states
- Якщо для цієї сторінки вже є empty state, покращити його.
- Якщо немає — додати простий empty state для випадку, коли записів немає.
- Не додавати складну логіку, тільки шаблонний UI-рівень.

7. Reusable structure
- За можливості винести повторювані частини в Twig partials/components:
  - page header;
  - index toolbar;
  - data table wrapper;
  - badge;
  - detail panel;
  - empty state.
- Не переписувати всю сторінку повністю, якщо можна зробити акуратний перший крок.
- Структура має бути придатна для повторного використання на інших CRUD index-сторінках.

Очікуваний результат:
- Сторінка платежів має виглядати як сучасна CRUD index-сторінка адмінки.
- Основний список має бути легше сканувати.
- Вибраний запис має бути очевидним.
- Деталі запису мають бути візуально відокремлені.
- UI-рішення мають бути універсальними для інших сторінок адмінки.
- Бізнес-логіка не повинна змінитися.
