Потрібно виконати фінальне UX/UI-полірування сторінки створення/редагування замовлення.

Не змінювати бізнес-логіку, routes, services, form field names, JS selectors, data attributes і translation keys без окремого погодження.
Не додавати нові залежності.
Не переписувати сторінку повністю.
Стилі мають відповідати існуючому стилю проєкту.

Задачі:

1. Виправити відображення ручної знижки
- для ручної знижки потрібно зробити перемикач
- якщо ручна знижка активна замінити селект вибору знижки на інпут поле

2. Уніфікувати формат чисел і сум
- У полях ціни не показувати сирий decimal-формат типу "49600,0000" або "6900,0000".
- Форматувати ціни у UI як "49 600.00" / "6 900.00" або у форматі, який уже використовується в підсумках.
- Не показувати зайві дублікати типу "10 % (10%)" + ще окремо "10%".
- Для відсотків показувати компактний формат: "10%", "5%", "Без знижки".

3. Перекласти системні тексти
- "No discount" замінити на "Без знижки".
- "manual" замінити на "вручну".
- "Status changed from ready_to_ship to draft." не показувати англійським технічним текстом.
- У блоці історії показувати людський текст: "Готове до відправки → Чернетка" або доступні перекладені назви статусів.
- Не змінювати назви складів, якщо вони є даними з бази.

4. Покращити production-позиції
- Для позицій типу "Виготовити під замовлення" не показувати "Наявність: 0 pcs".
- Замість цього показувати текст типу "Виробництво · під замовлення" або "Без складського залишку".
- Перевірити, щоб production-позиція не виглядала як помилка через нульову наявність.

5. Зробити кнопку видалення менш агресивною
- Іконка видалення товару не має бути головним візуальним акцентом картки.
- За замовчуванням зробити її нейтральнішою.
- Червоний акцент залишити для hover/focus або активного стану.
- Не змінювати саму логіку видалення.

6. Уніфікувати валюту
- У блоці підсумків додати валюту до сум або привести відображення до одного стилю з footer.
- "До сплати" має залишатися найпомітнішою сумою.
- Footer залишити sticky і не ламати його поведінку.

7. Коментарі
- Трохи збільшити клікабельну область швидких шаблонів коментарів, якщо це не ламає верстку.
- Залишити компактний вигляд chips/buttons.
- Не змінювати значення, яке вставляється в коментар, якщо це зав’язано на поточну логіку.

Після змін показати:
- короткий summary;
- список змінених файлів;
- що перевірено вручну.
